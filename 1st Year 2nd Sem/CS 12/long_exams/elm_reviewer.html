Lecture 15 · Introduction

What is Elm?

Elm is a purely functional language for building front-end web apps. Think of it as a very opinionated Python that compiles to JavaScript — but where the compiler catches almost every bug before you even run the code.

Purely Immutable

Nothing can change. No variable can be reassigned, no list can be mutated. This sounds limiting but makes code predictable and bug-free.

Statically Typed

Like Python with strict type hints everywhere. Elm infers types so you rarely need to write them explicitly — the compiler figures it out.

No Runtime Errors

If it compiles, it (almost certainly) works. No AttributeError, no TypeError, no undefined is not a function.

Elm programs run in the browser. The entry point is always main. You can try Elm live at https://ellie-app.com/ — no installation needed.

Hello World

import Html main = Html.text "Hello, World!"
1 Import the Html module so we can produce web content.
2 main is the program's entry point — always required.
3 Html.text creates a text node in the DOM. No parentheses needed around arguments.

In Elm, a "variable" is really a named constant. Once it equals something, it equals that forever. This forces you to think differently — instead of changing state step by step, you compute a new value from existing ones.

Lecture 15 · Control Flow

Conditionals

In Elm, if is an expression, not a statement. That means it always evaluates to a value and can be assigned to a variable — exactly like Python's ternary x if cond else y.

if / else if / else

🐍 Python — statement (can't assign)
if isWeekend:      # can't assign this
    mood = "happy"
else:
    mood = "sad"

# Ternary (expression):
mood = "happy" if isWeekend else "sad"
🌳 Elm — always an expression
mood =
    if isWeekend then
        "happy"
    else
        "sad"

-- One-liner:
mood = if isWeekend then "happy" else "sad"
The else branch is mandatory. In Python you can have if without else. In Elm you cannot — the compiler needs to know what value is produced in every case.

Chaining with else if:

elm — else if chaining
mood =
    if isRaining then
        "gloomy"
    else if hasExam then
        "scared"
    else if isWeekend then
        "happy"
    else
        "sad"

case Expression

When you're checking equality against many specific values, case is cleaner than chained if. Think of it as Python's match statement (Python 3.10+) or a long chain of elif`s.

🐍 Python — match statement
match n:
    case 1: day = "Sunday"
    case 2: day = "Monday"
    case _: day = "Unknown"
🌳 Elm — case expression (returns a value)
day =
    case n of
        1 -> "Sunday"
        2 -> "Monday"
        3 -> "Tuesday"
        _ -> "Unknown day"
_ is the wildcard — it matches anything. You'll use it constantly in Elm, especially to ignore carried data or provide a catch-all branch.

let Expression

The let expression lets you define temporary variables scoped to a block. Python equivalent: assigning temporary variables inside a function body, but in Elm they're only visible within the in part.

let x = 11 y = x + 1 -- can use x here in x + y -- the result
1 let opens a block for local definitions. All definitions must be indented more than the let keyword.
2 Later definitions can reference earlier ones (y uses x).
3 in is followed by the single expression that the entire let...in block evaluates to.
4 x and y do not exist outside this block — they are truly local.
Shadowing is flagged. If you define a local variable with the same name as an outer one, Elm will warn you. This avoids subtle bugs from accidentally hiding outer values.

Statements vs Expressions — The Key Mental Shift

Almost everything in Elm is an expression (produces a value)

🚫 STATEMENT (Python)

Cannot be assigned to a variable. Side-effectful. Examples: if statement, for loop, print() call.

✅ EXPRESSION (Elm)

Evaluates to a value. Can be assigned. In Elm: if, case, let...in, function calls, operators — all expressions.

Lecture 15 · Functions

Functions

Functions are the primary building blocks of Elm. They look deceptively simple but behave differently from Python — especially in how arguments are passed and how types work.

Declaring & Calling Functions

🐍 Python
def double(n):
    return n * 2

double(5)    # Returns 10
min(1.2, 1.55)  # Returns 1.2
🌳 Elm
double n = n * 2

double 5        -- Returns 10
min 1.2 1.55    -- Returns 1.2
No parentheses around arguments! In Elm, you separate arguments with spaces, not commas. Parentheses are only used for grouping: factorial (n-1) passes n-1 as one argument (otherwise Elm would interpret it as two separate things).

Recursion Instead of Loops

Since Elm has no while or for, repetition is done with recursion — a function calling itself.

factorial n = if n == 0 then 1 else n * (factorial (n - 1)) combination n k = let num = factorial n den = (factorial k) * (factorial (n - k)) in num // den
1 Base case: factorial 0 = 1. Every recursive function needs one.
2 Recursive case: multiply n by factorial (n-1). Parentheses group the argument.
3 combination uses a let block for clarity — splitting numerator and denominator into named sub-expressions.
4 // is integer division (discards remainder).

Type Signatures

Type signatures sit on the line above the function definition. They're optional (Elm infers them) but serve as great documentation and catch type errors early.

elm — function type signatures
-- Syntax: functionName : InputType1 -> InputType2 -> ReturnType

double : Int -> Int
double n = n * 2

combination : Int -> Int -> Int
combination n k = -- takes 2 Ints, returns 1 Int
    ...

parityStr : Int -> String
parityStr n = if isOdd n then "odd" else "even"
Reading a type signature
combination
:
Int
→
Int
→
Int

Read as: "combination takes an Int, then another Int, and returns an Int." The last type is always the return type.

Pipeline Operator |>

The pipeline operator |> passes the value on the left as the last argument of the function on the right. It makes chained transformations readable — like Unix pipe | in the terminal.

-- Without pipeline (nested, hard to read): List.reverse (List.range 1 5) -- With pipeline (reads left-to-right): List.range 1 5 |> List.reverse -- Real example from Main.elm: List.repeat c 0 |> List.repeat r -- Same as: List.repeat r (List.repeat c 0)
1 Nested calls read inside-out, which is confusing. The pipeline reads top-to-bottom, like a recipe.
2 List.range 1 5 produces [1,2,3,4,5], which is piped as the last arg to List.reverse.
3 In the zeroMatrix example: first create a row of zeros, then repeat that row r times to make a 2D matrix.
Lecture 16 · Immutable Data Types

Lists

List a is Elm's go-to sequence type. Like Python lists, but immutable (you never modify one — you compute a new one) and homogeneous (all elements must be the same type).

Creating Lists

elm — list creation
-- Literal syntax:
x = []              -- Empty list (type: List a)
y = [1, 2, 3]       -- List Int
z = ["a", "b"]      -- List String

-- List.range start end → [start, start+1, ..., end]
List.range 1 5     -- [1,2,3,4,5]
List.range 5 1     -- [] (empty if start > end)

-- List.repeat n value → list of n copies of value
List.repeat 3 "hi"  -- ["hi","hi","hi"]
List.repeat 5 0    -- [0,0,0,0,0]

-- (::) cons operator — prepend to list:
1 :: [2, 3]          -- [1,2,3]
1 :: 2 :: 3 :: []  -- [1,2,3]
List as a chain of cons cells (linked list)

[1, 2, 3] is secretly 1 :: (2 :: (3 :: [])). The head is fast to access; random access is slow (unlike Python lists).

Maybe: Safe Absence of Values

What does List.maximum [] return? The list is empty — there's no maximum. In Python this would throw an exception. In Elm, the return type is Maybe a — it either has a value (Just x) or is absent (Nothing).

Maybe a — exactly two possibilities
Just 100
← List.maximum [10, 100, 20]
Nothing
← List.maximum []
🐍 Python — Optional (same idea)
from typing import Optional

def safe_max(lst) -> Optional[int]:
    if not lst:
        return None
    return max(lst)

result = safe_max([1,2,3])
if result is not None:
    print(result)
else:
    print("empty!")
🌳 Elm — Maybe (forced to handle both)
-- Option 1: case expression
case List.maximum [1,2,3] of
    Just val -> "max is " ++ String.fromInt val
    Nothing  -> "empty!"

-- Option 2: withDefault (provide a fallback)
List.maximum [] |> Maybe.withDefault 0
-- returns 0 if Nothing, else the value
Maybe.withDefault fallback (maybeValue) is the quick way to "unbox" a Maybe when you have a sensible default. Use case when you need different behavior for Just vs Nothing.

List.filter — Keeping Elements

Filter takes a predicate (a function that returns Bool) and a list, and returns only the elements where the predicate is True.

isOdd : Int -> Bool isOdd n = modBy 2 n /= 0 isEven : Int -> Bool isEven n = isOdd n |> not x = List.range 1 10 y = List.filter isOdd x -- [1,3,5,7,9] z = List.filter isEven x -- [2,4,6,8,10]
1 modBy 2 n gives remainder of n / 2. Note: in Elm it's modBy divisor dividend, not n % 2.
2 /= is "not equal" (Elm's unusual way to say !=).
3 isEven reuses isOdd via pipeline: result of isOdd n is piped into not.
4 List.filter keeps elements where the predicate returns True.

List.map — Transforming Every Element

List.map applies a function to every element and collects the results into a new list. It's the functional replacement for a for loop that transforms elements.

🐍 Python
def increment(n): return n + 1

x = [10, 20, 30]

# Imperative:
for i in range(len(x)):
    x[i] = increment(x[i])

# Functional (map):
y = list(map(increment, x))
# [11, 21, 31]
🌳 Elm
increment : Int -> Int
increment n = n + 1

x = [10, 20, 30]
y = List.map increment x
-- [11, 21, 31]

-- map with different types:
List.map parityStr [1,2,3]
-- ["odd","even","odd"]
List.map : (a → b) → List a → List b
[10, 20, 30]
→
map increment
→
[11, 21, 31]

Key insight: map can change the type of elements (Int → String is fine) but never the count. Three in, three out — always.

Lecture 16 · Immutable Data Types

Arrays & Tuples

Lists are efficient for sequential access. Arrays add random access (get element at index i in O(1)). Tuples group a fixed number of differently-typed values together.

Array Module

Array is not imported by default. You must write import Array exposing (Array). The module is Array; the type inside is also Array — which is why you need exposing (Array) to use it without a prefix.
elm — Array usage
import Array exposing (Array)

-- Creation from a List:
arr : Array Int
arr = Array.fromList [10, 20, 30]

-- Random access: returns Maybe a (might be out of bounds)
Array.get 0 arr    -- Just 10
Array.get 5 arr    -- Nothing (index out of bounds)

-- Set a value (returns a NEW array; original unchanged)
newArr = Array.set 2 100 arr
-- arr    == Array.fromList [10, 20, 30]  (unchanged!)
-- newArr == Array.fromList [10, 20, 100]

-- Other useful functions:
Array.length arr         -- 3
Array.push 40 arr         -- Array [10,20,30,40]
Array.toList arr          -- [10,20,30]
Array.slice 1 3 arr        -- Array [20,30]
Array.repeat 3 0          -- Array [0,0,0]
Array.toIndexedList arr    -- [(0,10),(1,20),(2,30)]
Immutability is real. Array.set does not change the original array — it returns a brand new one. Always capture the result: newArr = Array.set 0 99 arr. If you don't capture it, the change is lost.

Tuples

A tuple groups 2–3 values of (potentially) different types. Perfect for returning multiple values from a function without defining a full record.

🐍 Python
# Python tuples — any length, any types
point = (3, 4)
triple = (1, "hello", True)

x, y = point   # destructuring
🌳 Elm
-- Max 3 elements; use Records for more
point : (Int, Int)
point = (3, 4)

triple : (Int, String, Bool)
triple = (1, "hello", True)

-- Destructuring (only inside let):
let
    (a, b) = point    -- a=3, b=4
    (x, _, z) = triple -- _ means "ignore"
in
a + b -- 7
Lecture 17 · Records, Fold, Recursion

Records & Dictionaries

When you need more than 3 fields, use a Record (fixed field names, like a dataclass) or a Dict (dynamic keys, like a Python dict).

Records

A record is like a Python dataclass or named tuple — a fixed set of named fields with specific types.

-- 1. Define a type alias for the record shape type alias Class = { section : String , students : Int , handler : String } -- 2. Create an instance myClass : Class myClass = { section = "CS 12 FRU1" , students = 19 , handler = "Martinez" } -- 3. Access a field myClass.section -- "CS 12 FRU1" myClass.students -- 19 -- 4. "Update" (creates a NEW record) newClass = { myClass | students = myClass.students + 1 }
1 type alias gives a name to a record shape. Like @dataclass in Python.
2 Creation uses = inside the braces (not : like the type definition).
3 Access fields with record.fieldName — same as Python's obj.attr.
4 { myClass | students = 20 } makes a NEW record with only students changed. myClass is still 19. Immutability!

Dictionaries

Dict is Elm's equivalent of Python's dict — stores key-value pairs. Unlike records, keys are dynamic. Also immutable, so all "mutations" return a new Dict.

elm — Dict usage
import Dict exposing (Dict)

-- Create from a list of (key, value) pairs:
myDict = Dict.fromList [("a", 1), ("b", 2)]

-- Get (returns Maybe):
Dict.get "a" myDict    -- Just 1
Dict.get "z" myDict    -- Nothing

-- Insert (returns new Dict):
Dict.insert "c" 3 myDict   -- {"a":1,"b":2,"c":3}

-- Remove (returns new Dict):
Dict.remove "a" myDict    -- {"b":2}

-- Other functions:
Dict.member "a" myDict   -- True
Dict.size myDict          -- 2
Dict.keys myDict           -- ["a","b"]
Dict.values myDict         -- [1,2]
Dict.toList myDict         -- [("a",1),("b",2)]
Dict.isEmpty Dict.empty    -- True
🐍 Python dict
d = {"a": 1, "b": 2}
d["c"] = 3     # mutates d in place
del d["a"]    # mutates d in place
d.get("z")    # None (no Maybe!)
🌳 Elm Dict
d = Dict.fromList [("a",1),("b",2)]
d2 = Dict.insert "c" 3 d   -- new dict!
d3 = Dict.remove "a" d2   -- new dict!
Dict.get "z" d             -- Nothing
Lecture 17 · Fold / Reduce

Fold: The Universal Loop

Elm has no for or while. Instead, most "aggregate over a list" patterns are captured by fold. Understanding fold is essential to thinking in Elm.

The Pattern Behind Every Aggregation Loop

Common Python for-loop pattern → Fold
python — the universal aggregation template
elems = [...]
result = STARTING_VALUE         # accumulator
for elem in elems:
    result = FUNCTION(result, elem)  # reducer

Every sum, product, max, concat loop fits this template. The only things that change are STARTING_VALUE and FUNCTION.

foldl and foldr

elm — List.foldl and List.foldr signatures
-- Both have the same signature!
List.foldl : (a -> b -> b) -> b -> List a -> b
List.foldr : (a -> b -> b) -> b -> List a -> b
--           REDUCER        START  LIST     RESULT
foldl trace: sum [1, 2, 3] starting from 0
acc = 0
+
elem = 1
→
acc = 1
acc = 1
+
elem = 2
→
acc = 3
acc = 3
+
elem = 3
→
acc = 6 ✓
elm — classic folds
sum : List Int -> Int
sum nums = List.foldl (+) 0 nums

product : List Int -> Int
product nums = List.foldl (*) 1 nums

nonNegMax : List Int -> Int
nonNegMax nums = List.foldl max 0 nums

concatStrs : List String -> String
concatStrs strs = List.foldr (++) "" strs

foldl vs foldr — Order Matters

foldl — Left to Right

Processes leftmost element first. For ["a","b","c"] with append:

append("c", append("b", append("a", "")))
→ append("c", append("b", "a"))
→ append("c", "ba") → "cba"
foldr — Right to Left

Processes rightmost element first. For ["a","b","c"] with append:

append("a", append("b", append("c", "")))
→ append("a", append("b", "c"))
→ append("a", "bc") → "abc"
For commutative operations (addition, multiplication — order doesn't matter), use either. For non-commutative ones (string append, list cons), the choice of foldl vs foldr changes the result.

Intermediate State with Tuples

What if your reducer needs to track extra state — like a counter for "which iteration am I on"? Use a tuple as the accumulator.

extend "abc" → "abbccc" — needs to track position k

The accumulator is a pair (answer, k) — the string built so far, and the current position count.

("", 1)
+
'a'
→
("a", 2)
("a", 2)
+
'b'
→
("abb", 3)
("abb", 3)
+

extend : String -> String extend str = let reducer : Char -> (String, Int) -> (String, Int) reducer ch acc = let (answer, k) = acc nextAnswer = answer ++ String.repeat k (String.fromChar ch) nextK = k + 1 in (nextAnswer, nextK) (finalAns, _) = String.foldl reducer ("", 1) str in finalAns
1 The reducer is defined locally inside let. Its accumulator type is a tuple (String, Int) — the answer string and the current repeat count k.
2 Destructuring (answer, k) = acc unpacks the tuple inside another let.
3 String.repeat k ch_str repeats the character string k times.
4 String.foldl works character by character on a String. Starting value is ("", 1).
5 (finalAns, _) — we only need the answer, so we discard the final k with _.
Lecture 18 · Algebraic Data Types

Algebraic Data Types

Elm lets you create new types that can be exactly one of several variants. This is Elm's most powerful concept for data modeling, and the key to making invalid states impossible to represent.

type vs type alias

type alias — rename an existing type
-- Just a new name for an existing shape
type alias Name = String
type alias Model = Int
type alias Class =
    { section : String
    , students : Int
    }

Like TypeAlias = OriginalType in Python typing. No new type is created — just a shorter name.

type — create a brand new type
-- Creates a new type with named variants
type Bool = True | False
type Standing =
    Freshman | Sophomore
    | Junior | Senior | Other
type DayOfWeek =
    Sunday | Monday | Tuesday
    | ...

Like Python's Enum, but much more powerful — variants can carry data too.

Types as Sets — Why It Matters

Cardinality (number of possible values) of types

Product Type (AND — record)

type alias R = { a: Bool, b: Bool }
|R| = |Bool| × |Bool| = 2 × 2 = 4 values

Sum Type (OR — union)

type Standing = Freshman | Sophomore | Junior | Senior | Other
|Standing| = 1+1+1+1+1 = 5 values

Choose the type with the exact right number of states. Using String for student standing has ∞ values and allows nonsense like "Freshman " or "fr3shm4n". A sum type with 5 variants allows exactly 5 — no more, no less.

Tagged Unions — Variants with Data

Variants can carry data. This is like a Python discriminated union or a sealed class in Kotlin — each variant has a tag and optionally some payload.

type CrSectionSlots = WithSlots Int | Full | Overbooked Int | Dissolved -- Maybe is just a tagged union too! type Maybe a = Just a | Nothing -- Creating values: slot1 = WithSlots 14 slot2 = Full slot3 = Overbooked 3 slot4 = Dissolved
1 WithSlots Int — the variant tag is WithSlots, and it carries one Int (the number of remaining slots).
2 Full and Dissolved carry no data — they're like singleton enum values.
3 Maybe a is generic — the a is a type variable (like Python's Generic[T]). Just 5 is a Maybe Int; Just "hi" is a Maybe String.
4 To create a value, write the variant name followed by any carried data.
CrSectionSlots — four possible states
WithSlots14 slots left
FullNo data
Overbooked3 over capacity
DissolvedNo data

Pattern Matching on Tagged Unions

Use case to destructure and handle each variant. Elm checks exhaustiveness — if you forget a branch, it won't compile.

toSlotStr : CrSectionSlots -> String toSlotStr slots = case slots of WithSlots left -> "OPEN: " ++ String.fromInt left Full -> "FULL" Overbooked over -> "OVERBOOKED by " ++ String.fromInt over Dissolved -> "DISSOLVED" -- Wildcard to ignore carried data: hasSlots : CrSectionSlots -> Bool hasSlots slots = case slots of WithSlots _ -> True _ -> False
1 Each branch pattern starts with the variant name. For variants with data (WithSlots left), the name after the tag (left) binds the carried value locally.
2 Full and Dissolved have no data, so the pattern is just the tag name.
3 All four variants must be covered. Remove any branch and Elm won't compile — it tells you exactly which cases are missing.
4 WithSlots _ — we don't need the number, so we use _ to ignore it. The _ in the second branch catches all other variants.
Exhaustiveness checking is one of Elm's killer features. If you add a new variant to a type later, Elm will immediately point to every case expression that needs to be updated. This prevents the "forgot to handle the new case" bug.

Food Ordering Example (Data Modeling)

elm — modeling a food ordering system
type Dip = Ketchup | BBQSauce
type SugarPercent = Percent0 | Percent25 | Percent50 | Percent75 | Percent100

type FoodItem
    = Tapsilog { vinegar : Bool, atchara : Bool }
    | Water

-- Using them:

        , Fries Ketchup

        ]

        Tapsilog _ -> 150   -- ignore the record details

Lectures 19–20 · MVU Architecture

The MVU Architecture

MVU (Model-View-Update), also called The Elm Architecture (TEA), is how every interactive Elm program is organized. Once you get it, it clicks forever.

The Big Picture

MVU Cycle
Model
State of the app
e.g. counter = 5
→
view renders UI
View
UI from state
HTML on screen
→
user clicks → Msg
Update
Msg + Model → Model
produces new Model
→
new state loops back
Model'
Updated state
e.g. counter = 6
Model

The complete state of your app at any moment. A single data structure (often a record). Think of it as your database.

View

A pure function Model → Html Msg. Given the current state, produce the HTML. No side effects. Same input → same output, always.

Update

A pure function Msg → Model → Model. Given a message (user action) and current state, produce the new state.

Building a Counter App — Step by Step

Step 1: Define Model and initial state

elm — step 1: model
type alias Model = Int     -- The counter is just an Int

init : Model
init = 0                   -- Starts at 0

Step 2: Define all possible user actions (Msg)

elm — step 2: msg
type Msg
    = MsgIncrement
    | MsgDecrement
    | MsgReset     -- Added later

Step 3: Define update — how each message changes the state

elm — step 3: update
update : Msg -> Model -> Model
update msg model =
    case msg of
        MsgIncrement -> model + 1
        MsgDecrement -> model - 1
        MsgReset     -> 0

-- Key: update is a PURE function. It just computes a new value.
-- No mutation, no DOM manipulation, no network calls here.

Step 4: Define view — HTML from state

import Html exposing (Html, button, div, p, text) import Html.Events exposing (onClick) view : Model -> Html Msg view model = div [] [ button [ onClick MsgIncrement ] [ text "+" ] , p [] [ text (String.fromInt model) ] , button [ onClick MsgDecrement ] [ text "-" ] , button [ onClick MsgReset ] [ text "Reset" ] ]
1 Html Msg means "an HTML node that can emit Msg values." The type parameter tracks what kinds of messages buttons etc. can fire.
2 div attrs children — first arg is a list of HTML attributes, second is a list of child nodes.
3 onClick MsgIncrement attaches an event listener. When clicked, MsgIncrement is sent to update.
4 text makes a text node. It takes a String, so we must convert model (an Int) with String.fromInt.
5 The entire view is ONE Html Msg value. You can't return two top-level nodes — wrap them in a div.

Step 5: Wire it together with main

elm — complete main
import Browser

main : Program () Model Msg
main = Browser.sandbox
    { init   = init
    , update = update
    , view   = view
    }

-- From SumIntegers.elm type Msg = MsgNumOne String | MsgNumTwo String type alias Model = { intOne : String , intTwo : String , display : String } update msg model = let updatedModel = case msg of MsgNumOne s -> { model | intOne = s } MsgNumTwo t -> { model | intTwo = t } newDisplay = addTwoIntegerStrings updatedModel.intOne updatedModel.intTwo in { updatedModel | display = newDisplay } view model = div [] [ p [] [ text model.display ] , input [ onInput MsgNumOne ] [] , input [ onInput MsgNumTwo ] [] ]

2 The Model stores both input strings and the display text. All state lives in one place.

Dynamic Counters — Real-World MVU

The DynamicCounters.elm demo shows a Model with a Dict of counters, each with its own ID, and messages that carry the counter's ID.

type Msg = MsgNewCounter | MsgIncrement Int -- carries counter ID | MsgDecrement Int | MsgReset Int | MsgDelete Int type alias CounterInfo = { cid : Int, count : Int } type alias Model = { nextId : Int , counters : Dict Int CounterInfo } init : Model init = { nextId = 0, counters = Dict.empty }
1 Messages carry the counter's ID so update knows which counter to affect. E.g. MsgIncrement 3 increments counter #3.
2 CounterInfo is a record with a counter's ID and current count.
3 The Model's counters is a Dict Int CounterInfo — a map from counter ID to its info. Adding a counter = inserting into this dict.
4 nextId tracks the next available ID (auto-increment, like a database primary key).
elm — dynamic counters update function (key parts)
update : Msg -> Model -> Model
update msg model =
    case msg of
        MsgNewCounter ->
            { model
            | nextId = model.nextId + 1
            , counters = Dict.insert model.nextId
                { cid = model.nextId, count = 0 }
                model.counters
            }

        MsgIncrement cid ->
            let
                cinfo = Dict.get cid model.counters
                    |> Maybe.withDefault defaultInfo
            in
            { model | counters =
                Dict.insert cid { cinfo | count = cinfo.count + 1 }
                    model.counters }

        MsgDelete cid ->
            { model | counters = Dict.remove cid model.counters }

        -- MsgDecrement and MsgReset are similar to MsgIncrement

Http & Commands (Browser.element)

For network requests, you need Browser.element instead of Browser.sandbox. The update function now returns (Model, Cmd Msg) — the new state plus a command to execute.

Browser.sandbox vs Browser.element
Browser.sandbox

For pure apps with no side effects. update returns just a Model. No HTTP, no randomness.

update : Msg -> Model -> Model
Browser.element

For apps that talk to the world. update returns a tuple of (new model, command). Cmd.none means "no command".

update : Msg -> Model -> (Model, Cmd Msg)
elm — fetching data from an API
import Http

type Model
    = LoadingJoke
    | ShowingJoke String
    | ErrorPage String

type Msg
    = MsgGotJoke (Result Http.Error String)

-- Result is like Maybe, but with error info:
-- Ok value  → success
-- Err error → failure with reason

getJoke : Cmd Msg
getJoke =
    Http.get
        { url    = "https://v2.jokeapi.dev/joke/programming?format=txt"
        , expect = Http.expectString MsgGotJoke
        }

init : () -> (Model, Cmd Msg)
init _ = (LoadingJoke, getJoke)  -- fetch on start

update : Msg -> Model -> (Model, Cmd Msg)
update msg model =
    case msg of
        MsgGotJoke result ->
            case result of
                Ok joke  -> (ShowingJoke joke, Cmd.none)
                Err err  -> (ErrorPage (Debug.toString err), Cmd.none)

view : Model -> Html Msg
view model =
    case model of
        LoadingJoke     -> text "Loading..."
        ShowingJoke joke -> text joke
        ErrorPage err    -> text err

main = Browser.element
    { init          = init
    , update        = update
    , subscriptions = \_ -> Sub.none
    , view          = view
    }
Result error value is like Maybe but the "unhappy path" also carries information. Ok 42 means success with value 42. Err "network timeout" means failure with a reason. Handle with case just like Maybe.

The 5 Things Elm Beginners Must Remember

No reassignment. x = x + 1 is a compile error. Compute new values instead.
No for/while loops. Use List.map, List.filter, List.foldl, or recursion.
if requires else. Always. Every branch must return a value of the same type.
No implicit type conversion. Can't mix Int and Float. Use toFloat or round.
Mutation returns new values. List.filter, Array.set, Dict.insert all return a new container. The original is unchanged.
Exhaustiveness is your friend. case must cover all branches. If you add a variant, the compiler tells you where to update.
